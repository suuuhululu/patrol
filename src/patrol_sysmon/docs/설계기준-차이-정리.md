# 시스템 모니터 현재 구현과 설계 기준의 차이

작성: 2026-09-07 KST · 작성 팀: System monitor
기준 문서: [설계 기준 결정](../../../docs/decisions/2026-09-07-design-baseline.md), [AGENTS.md](../../../AGENTS.md), [interfaces.md](../../../docs/interfaces.md)

이 문서는 `src/patrol_sysmon/`에 올린 코드가 **현재 어떤 상태인지**와 확정 기준과 다른 지점을 그대로 적는다. 합의 없이 공용 코드를 바꾸지 않기 위해, 코드는 개발하던 상태 그대로 올리고 차이만 여기에 남긴다.

## 1. 공용 메시지 패키지 이름 통일 (2026-09-08 완료)

- 확정: 공용 ROS 메시지 패키지는 `patrol_interfaces`, 경로는 `src/patrol_interfaces/`
- 조치 완료: 코드 44곳의 `parking_interfaces`를 `patrol_interfaces`로 바꾸고, 중복이던 `src/patrol_sysmon/parking_interfaces/`를 지웠다
- 공용 패키지에 없던 메시지 9개(`DetectionEvent`·`DetectionCandidate`·`EvidenceChunk`·`IngestionAck`·`KeepoutStatus`·`PatrolVisit`·`EStopState`·`ControlHeartbeat`·`MissionCommandAck`)를 `src/patrol_interfaces/msg/`로 옮겼다. **기존 7개 정의는 바꾸지 않았다**
- 이름이 겹치는 `RobotStatus`·`CameraState`·`PatrolReport`·`MissionCommand`·`DriveToken`은 **공용 정의를 그대로 채택**하고 시스템 모니터 변환기를 맞췄다

### 겹치는 정의를 채택하며 생긴 차이

앞서 "문자열 교체로 끝난다"고 적었으나 실제로는 필드와 enum 값이 달라 변환기를 고쳤다. 어느 정의로 빌드해도 같은 코드가 동작하도록 처리했다.

| 항목 | 공용 계약 | 기존 정의 | 처리 |
| --- | --- | --- | --- |
| `RobotStatus.pose` | `PoseWithCovarianceStamped` | `PoseWithCovariance` | 중첩 단계를 찾아 내려가 좌표를 읽는다 |
| `RobotStatus.message_id` | 없음 | 있음 | `source_session_id`+`robot_id`+`status_sequence`로 같은 뜻의 키를 만든다 |
| `RobotStatus.last_valid_pose` | pose 전체 | 시각만 | 어느 쪽이 와도 시각을 꺼낸다 |
| `CameraState` state 값 | `EXITED=2`·`PARKED=3`·`EXITING=4` | `PARKED=2`·`EXITING=3`·`EXITED=4` | **숫자 대신 상수 이름으로 해석한다.** 숫자표를 그대로 두면 출차를 주차 완료로 잘못 저장한다 |
| `PatrolReport.finished_at` | `finished_at` | `ended_at` | 둘 다 받는다 |
| `PatrolReport.patrol_id` | 없음 | 있음 | 없으면 `mission_id`로 순찰 회차를 잇는다 |
| `PatrolReport` 중복 키 | 순번 필드 없음 | `message_id` | `report_id`를 중복 제거 키로 쓴다 |

### 남은 합의 항목

- `/control/estop`의 타입: 2026-09-08 계약(interfaces.md 3.1절)대로 시스템 모니터가 `EStop`을 구독한다. `EStop.msg`에서 `latched`를 제거하고 reason 상수·`TARGET_ALL`을 넣었으며 `EStopState.msg`는 삭제했다. reason 우선순위는 **TBD-IF-004**다
- 공용 `PatrolReport`에 `planned_visit_count`·`completed_visit_count`가 없어 0으로 저장된다. 순찰 진행률 표시가 필요하면 필드 추가를 협의한다
- 공용 `RobotStatus`의 `safety_state`는 2026-09-08 결정 수치(0~5)로 저장·표시한다. `.msg`에 상수가 반영되면 이름으로 읽도록 바꾼다

### 공용 패키지에 없는 메시지

현재 `src/patrol_interfaces/`에는 `RobotStatus`, `MissionCommand`, `PatrolReport`, `DriveToken`, `EStop`, `CameraState` 6개가 있다. 시스템 모니터가 구독 중인 아래 메시지는 아직 공용 패키지에 없다.

| 메시지 | 사용 토픽 |
|---|---|
| `DetectionEvent` | `/{robot}/detection/event` |
| `EvidenceChunk` | `/{robot}/detection/evidence` |
| `IngestionAck` | `/{robot}/ingestion_ack` |
| `KeepoutStatus` | `/{robot}/keepout/status` |
| `PatrolVisit` | `/{robot}/patrol_visit` |
| `DetectionCandidate`, `ControlHeartbeat` | 계약 정의만 사용. `MissionCommandAck`·`EStopState`는 2026-09-08 삭제 |

공용 `.msg`는 interfaces.md에 확정된 내용만 옮긴다. 2026-09-08에는 `EStop`·`ControlHeartbeat`·`MissionCommand`(parameters_json 제거)·`CommandCheck`·`RobotStatus`(safety 상수)를 계약대로 맞췄고, 이로 인한 AMR 코드 후속 작업(`latched` 참조 제거 등)은 AMR 담당이 처리한다.

## 2. 시스템 모니터의 판단 범위

- 확정: 시스템 모니터의 사용 범위는 UI다. 관제가 제공한 상태와 이벤트를 표시하며 운영 판단을 담당하지 않는다
- 현재 코드: 토픽 25개를 직접 구독해 검증·저장하고, 아래 값을 **자체 계산**해 표시한다
  - 로봇 STALE(마지막 수신 후 15초)
  - 순찰 UNREPORTED(방문 기록은 있고 결과 보고가 없는 순찰)
  - CCTV permit 미수신 경고
  - E-stop 수신 지연
  - 증적 조립 지연·누락(경과 시간 기준)
- 같은 결정문의 완충 문구에 따라 **저장 기능은 시스템 모니터가 유지**한다. 판단만 관제로 옮기는 방향으로 읽었다
- 필요한 조치: 관제가 `/control/operational_state`·`/control/operational_event`를 발행하면 판단 값을 그 토픽에서 받고, 현재 자체 계산은 토픽 미수신 시 대체 표시로 남긴다. 두 경로가 동시에 동작하면 화면에 서로 다른 값이 보일 수 있으므로 전환 시점을 합의한다

## 3. 저장 백엔드

- 제안: PostgreSQL 권장
- 현재 코드: SQLite(WAL). 25개 테이블, 증적·지도·영상은 파일로 저장하고 DB에는 경로만 둔다
- 측정: 조회자 4명 동시, 상태 4 Hz·영상 20 Hz 부하에서 대시보드 p95 54 ms, 통합 이력 p95 32 ms, 실패 0건. 5.2초 write lock 주입 시 5초 timeout 뒤 HTTP 503으로 구분되고 해제 후 30 ms로 복구
- 판단: 데모·통합시험 범위에서는 SQLite를 유지하고 PostgreSQL은 운영 전환 과제로 둔다

## 4. 아직 구현하지 않은 수신 항목

`drive_token`, `heartbeat`는 관제 ↔ AMR 안전 계층 토픽이라 시스템 모니터가 관측할지 정해지지 않았다. 순찰 교대(`handovers`) 입력 경로도 없다.

## 5. 현재 상태 요약

- 활성 구독 25개, 발행은 `ingestion_ack` 2개뿐이다. 명령·token·Keepout·E-stop을 발행하지 않는다
- 단위·요청·격리 DDS 시험 115개 통과(같은 PC 안의 가상 publisher 기준)
- 실제 AMR·비전·관제 발행, 운영 domain 6, PC 간 네트워크는 아직 시험하지 않았다
