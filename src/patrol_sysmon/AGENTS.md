# Sysmon 구현 및 기록 지침

사용자는 단계별로 구현하며, 완성 후 30분 코드리뷰를 진행한다. 이 폴더의 후속 작업에서는 다음을 따른다.

- 사용자가 요청한 단계와 기존 합의 범위에 맞춰 구현한다. 완료 기능과 예정 기능을 구분한다.
- day5 예제의 활용 부분과 변경 이유를 기록한다. 기능을 실행 파일 하나에 몰아넣지 않는다.
- 기능 함수와 주요 분기·저장 처리에는 한국어 주석으로 역할과 이유를 설명한다.
- 구현·수정 후 `docs/implementation-log.md`에 목적, 변경 파일·함수, 실행 흐름, 설계 이유, 검증 결과, 남은 일을 추가한다. 과거 기록은 삭제하지 말고 수정 이력을 덧붙인다.
- 실제 실행한 검증만 결과로 기록한다. 이전 실행 결과 인용과 이번 실행을 구분하고, 테스트 개수만으로 모든 기능이 검증됐다고 표현하지 않는다.
- `docs/code-review-30min.md`의 코드 탐색 경로·시연·질문 답변을 현재 구현에 맞게 갱신한다. 미래 기능을 이미 구현한 것처럼 설명하지 않는다.
- 단계 완료 여부와 실행 방법이 바뀌면 `README.md`도 갱신한다.
- 문서와 시연 자료에는 실제 비밀번호, 세션 키, 세션 쿠키를 기록하지 않는다.
- 이벤트 증거 이미지는 AMR1 또는 AMR2 중 실제 감지 로봇과 연결한다. 수신 확인 알림과 다음 행동 명령은 별도 개념이며, 자동 발행 정책은 아직 미확정이다.
- 변경 내용에 맞는 검증을 한다. 문서만 변경한 경우 링크·코드 설명의 일치를 확인하면 되며 불필요하게 전체 테스트를 반복하지 않는다.
