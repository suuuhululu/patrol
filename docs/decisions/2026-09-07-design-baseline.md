# 설계 기준 우선순위와 역할 확정

결정일: 2026-09-07 · 근거: PM의 명시적 결정 · 적용: AMR·관제·비전·시스템 모니터의 설계 문서

## 확정 기준

1. 관제는 시스템 모니터와 분리된 노드로 동작한다. 제어 판단·명령·token·교대·안전 중재는 관제 책임이다.
2. 시스템 모니터의 사용 범위는 UI다. 관제가 제공한 상태와 이벤트를 표시하며 제어 명령 발행이나 운영 판단을 담당하지 않는다. 기존 문서의 DB·로그 설명은 표시할 데이터를 제공하는 지원 기능의 설계 자료로 읽으며, 이를 UI 자체의 제어 책임으로 해석하지 않는다. 이 결정만으로 저장 백엔드의 담당을 다른 팀에 재배정하지 않는다.
3. 공용 ROS 메시지 패키지 이름은 `patrol_interfaces`다. 작업 경로는 `src/patrol_interfaces/`다. 이전 패키지 표기는 이 명칭으로 통일한다.
4. 설계 충돌 시 최신 PM 명시 결정 → [System design 원본](https://docs.google.com/document/d/1mEg2aTPkAJdhlMyAoyU2TxsvMpzounh4gX0ePGqAxHM/edit)의 확정 내용 → 원본에 맞춘 Git 기능 문서 순으로 적용한다. 시트의 과거 문구나 예시를 확정 설계보다 우선하지 않는다.
5. System design에서 정해진 사항을 다른 문서가 미정으로 표시하면 해당 표기는 낮은 버전으로 판단하고 기준 설계에 맞춘다. 단순히 `TBD`가 존재한다는 이유로 확정 내용을 다시 논의하지 않는다.

## 원본 확인 결과와 남은 경계

연결된 System design은 ACK·재전송, 일부 메시지 필드, 순찰 방문·재개 조건 등을 자체적으로도 TBD로 설명한다. Appendix A는 ACK 2초/3회를 확정 시험 기준으로 사용하지 않도록 명시한다. 따라서 현재 확인한 원본에서 미정인 값을 임의로 채우거나 시험 통과 기준으로 확정하지 않는다. 이후 원본에 확정 내용이 반영되면 해당 절·버전을 확인해 Git 문서에 적용한다.

System design 본문에 남은 과거 패키지 이름과 MD 우선 문구보다 이번 PM 결정의 명칭·우선순위를 먼저 적용한다. 확정 설계와 실제 구현·시험 완료는 구분한다.

## 변경 범위

이번 변경은 Git 설계 문서의 기준과 패키지 표기를 정리한다. 실행 코드·설정·DB는 변경하지 않는다. 진행률·업무 상태·마감일·통합 일정은 PM이 수동 수정하며, 노션과 스프레드시트는 이번 작업에서 변경하지 않는다.
