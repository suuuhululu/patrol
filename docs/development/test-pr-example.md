# 테스트 PR — PC 간 통신 검토 연습

이 문서는 PR 작성·리뷰·수정 방법을 연습하기 위한 예시다. 실제 통신 오류가 발생했다는 보고가 아니며, 코드·메시지·설정은 바꾸지 않는다. 연습 PR은 main에 병합하지 않는다.

## 연습 상황

AMR에서 보내는 로봇 상태를 관제가 받고, 시스템 모니터는 UI에 표시하려고 한다. 서로 같은 메시지 이름을 쓰는지 확인한다. 실제 기준은 `patrol_interfaces`와 [인터페이스 문서](../interfaces.md)다.

## PC별 확인 요청 예시

| 대상 | 확인할 위치·기능 | 확인할 내용 | 현재 상태 |
| --- | --- | --- | --- |
| AMR1·AMR2 | src/patrol_amr/의 상태 발행 기능 | 공용 메시지 타입과 robot1·robot6 식별이 맞는지 | 연습용, 실제 코드 검토 안 함 |
| 관제 | src/patrol_control/의 상태 수신 기능 | AMR과 같은 타입·필드·단위를 사용하는지 | 연습용, 실제 코드 검토 안 함 |
| 시스템 모니터 | src/patrol_sysmon/의 UI 수신 기능 | 받은 상태를 표시하고 제어 명령을 발행하지 않는지 | 연습용, 실제 코드 검토 안 함 |
| 공용 메시지 | src/patrol_interfaces/ | 발행·수신 양쪽에서 같은 버전을 사용하는지 | 연습용, 실제 코드 검토 안 함 |

## 줄 댓글 연습

아래 문장을 Files changed에서 찾아 줄 옆의 +를 누르고 리뷰 의견을 남긴다.

**확인 결과: 아직 작성하지 않았습니다.**

댓글 예시: “실제 통신 시험은 하지 않았다는 점과, 문서 링크 확인 결과를 나누어 적어 주세요.”

작성자는 같은 브랜치에서 위 문장을 수정하고 커밋·푸시한 뒤, 댓글에 변경 커밋과 확인 결과를 답한다. 코드에 손대지 않고도 PR 수정 과정을 연습할 수 있다.

## 완료 기준

- PR 본문에서 변경 목적·PC별 요청·검증 여부를 확인한다.
- PM 또는 통합 관리자가 줄 댓글을 남긴다.
- 작성자가 문서를 수정하고 같은 PR에 반영한다.
- 리뷰어가 반영 내용을 확인한다.
- 연습을 마치면 병합 대신 Close pull request로 종료한다.
