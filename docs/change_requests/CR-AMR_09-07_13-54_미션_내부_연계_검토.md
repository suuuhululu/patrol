## 변경 이유

> **현행 계약 안내:** 이 요청서의 TBD-IF-009 미정·제안 표현은 작성 당시 이력이다. 최종 속도 토픽·타입·발행자·Q-17은 [TBD-IF-009 확정 요청서](CR-AMR_09-08_08-31_최종_cmd_vel_경로와_주행_후보_토픽.md)와 [interfaces.md](../interfaces.md)가 기준이다. 아래 초안으로 현행 계약을 되돌리지 않는다.

미션 실행기는 검증된 MissionCommand를 시나리오로 실행하고 내부 mission,
waypoint, command 결과를 보유한다. 팀원 차트는 status reporter의
`mission_status callback`과 Nav2의 `cmd_vel_safe · TwistStamped` 입력을
제안하지만, 현재 공용 문서는 두 연결의 토픽·타입·필드·QoS를
TBD-IF-003·009로 유지한다. 임의 연결을 만들면 status reporter와 local
safety 구현에 충돌할 수 있어 합의 전에는 주행을 기본 차단한다.

## 변경 전 → 변경 후

현재 기준:

- mission supervisor → status reporter 내부 연결의 정확한 계약이 없다.
- Nav2/yaw 주행 후보 → local safety → 구동부의 이름과 Twist 계열 타입이
  TBD-IF-009다.
- STOP/CANCEL 상태 보존 차이와 재개 지점은 TBD-AMR-005다.

제안:

1. 별도 ROS 노드인 status reporter가 mission 상태를 받아야 한다면
   `/{robot}/mission_status_internal` 상대 토픽과
   `patrol_interfaces/msg/MissionStatus`를 사용한다. 최소 후보 필드는
   `header`, `command_id`, `mission`, `waypoint_index`, `scan_active`다.
   정확한 enum·미션 종료 결과·QoS는 TBD-IF-003 합의로 확정한다.
2. 팀원 차트와 같이 Nav2 후보 출력은 로봇 namespace 아래
   `cmd_vel_safe`의 `geometry_msgs/msg/TwistStamped`, local safety의 유일한
   최종 출력은 namespace 아래 `cmd_vel`로 제안한다. 구동부가 Twist를
   요구하면 변환 위치와 단일 발행자를 함께 명시한다.
3. 위 연결이 합의되고 IT-16에서 안전 우회 경로가 없음을 확인할 때까지
   mission launch의 `safety_path_ready` 기본값은 `false`로 유지한다.
4. STOP/CANCEL은 현재 실행 goal을 취소하고 자동 재출발하지 않는 공통
   부분만 구현한다. pause/checkpoint 보존 차이는 TBD-AMR-005 결정 뒤
   반영한다.
5. Undock timeout은 확정값이 없어 임의 수치를 두지 않는다. Action server와
   결과 대기 중 STOP/CANCEL은 받을 수 있으며, 별도 timeout이 필요하면
   TBD-AMR-004·005 검토에서 값을 결정한다.

위 내용은 제안이며 아직 공용 계약으로 확정되지 않았다.

## 영향과 적용 순서

먼저 공용 메시지와 속도 경계를 합의하고 `interfaces.md`에 결정 일자·근거를
기록한다. 그 뒤 AMR status reporter와 local safety를 반영하고, 마지막으로
mission launch의 내부 publisher/remap과 `safety_path_ready`를 활성화한다.
혼합 버전에서는 미션 주행을 허용하지 않는다. 실패 시 파라미터를 false로
되돌리고 새 MissionCommand를 거부하며, 통신 복구만으로 자동 재개하지
않는다.
