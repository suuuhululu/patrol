## 변경 이유

`feat/amr-safety-status`로 이관한 공용 메시지 패키지는 디렉터리명이 `src/patrol_interfaces/`인데 `package.xml`과 CMake `project()`의 실제 ROS 패키지명은 `parking_interfaces`였다. 이관 시점의 `README.md`도 이 불일치를 그대로 기록하고 있었다.

이 상태에서는 `colcon build --packages-select patrol_interfaces`가 `ignoring unknown package`로 실패하고 빌드 산출 경로도 `install/parking_interfaces`가 되어, 확정 설계 문서의 표기를 그대로 따르는 다른 단위가 빌드·의존 선언·타입 조회에서 어긋난다. 실제로 재검증 중 위 명령이 0 packages로 끝나는 것을 관측했다.

PM 확정 결정 3항이 `patrol_interfaces`를 공용 명칭으로 지정했고, `main`의 [interfaces.md](../interfaces.md) 계약표도 이미 `patrol_interfaces/msg/...`로 갱신되어 있다. 문서 기준과 실제 패키지명을 일치시킨다.

## 변경 전 → 변경 후

계약 내용 변경이 아니라 패키지 식별자 변경이다. 아래 외의 차이는 없다.

| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| ROS 패키지명 (`package.xml` `<name>`, CMake `project()`) | `parking_interfaces` | `patrol_interfaces` |
| 빌드 선택 | `--packages-select parking_interfaces` | `--packages-select patrol_interfaces` |
| 설치 경로 | `install/parking_interfaces` | `install/patrol_interfaces` |
| 메시지 타입 이름 | `parking_interfaces/msg/<Name>` | `patrol_interfaces/msg/<Name>` |
| 디렉터리 경로 | `src/patrol_interfaces/` | 변경 없음 |
| 메시지 5종의 필드·상수·enum·주석 | — | 변경 없음 |
| 토픽 이름·QoS·시간 정책 | — | 변경 없음 |

메시지 5종은 MissionCommand, DriveToken, RobotStatus, PatrolReport, EStop이다. 이들의 필드 레이아웃과 TBD 상태는 이 요청서로 합의하지 않으며 [interfaces.md](../interfaces.md)와 [패키지 README](../../src/patrol_interfaces/README.md)의 기존 TBD-IF-001~004를 유지한다.

## 영향과 적용 순서

- 타입 이름이 바뀌므로 송신·수신 양쪽이 같은 명칭을 사용해야 한다. 한쪽만 이전 명칭을 쓰면 토픽 타입이 달라 pub/sub 매칭 자체가 성립하지 않는다. 필드 레이아웃은 동일하므로 부분 수신이나 값 오해석은 발생하지 않고, 증상은 '연결되지 않음'으로 나타난다.
- 현재 다른 단위에 구현 코드가 없어 혼합 버전 위험은 실질적으로 없다. 다른 단위가 구현을 시작하기 전에 확정하는 것이 비용이 가장 낮다.
- 이전에 `parking_interfaces`로 빌드한 워크스페이스가 있으면 `install/`, `build/`에 옛 패키지가 남아 조회 시 혼동될 수 있다. 해당 디렉터리를 지우고 다시 빌드한다. 저장소에는 `build/`, `install/`, `log/`가 `.gitignore`로 제외되어 있다.
- 실패 시 복구는 `package.xml`과 `CMakeLists.txt`의 이름을 되돌리고 재빌드하는 것으로 충분하다. 데이터·저장 스키마 영향은 없다.
- 안전 정책 영향 없음. 이 변경은 식별자에 한정되며 로컬 안전·속도 통제 동작을 바꾸지 않는다.
