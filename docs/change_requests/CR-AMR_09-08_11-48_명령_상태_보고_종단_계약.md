## 변경 이유

AMR은 `MissionCommand`의 재시작 영속 중복 제거, `RobotStatus` mission context, `PatrolReport` 생성·영속 복원까지 구현했다. 그러나 실제 ROS 수신→`CommandCheck`→mission 실행→상태·최종 report 경로를 연결하려면 아래 공유 계약이 필요하다.

- `CommandCheck.check_state` 세 값의 uint8 숫자
- command별 `target_id`, `target_pose`, `parameters_json` 필수·금지·스키마
- `COMMAND_ID_CONFLICT`를 `reason_code`와 `reason`에 표현하는 방법
- command 수락·실행·STOP·CANCEL·대체·재개 상태 전이표와 재시작 복구 정책
- 영속 `PatrolReport`의 재전송 트리거와 전송 완료 판정

이 값을 AMR이 임의로 정하면 관제의 ACK 해석, 명령 거절, 중복 실행 방지, 단절 후 결과 복구가 서로 달라질 수 있다.

## 변경 전 → 변경 후

| 항목 | 변경 전 | 변경 후(요청) |
|---|---|---|
| Check 상태 | ACCEPTED·EXECUTING·REJECTED 의미만 확정 | 세 uint8 값 확정 후 `CommandCheck.msg`·관제·AMR 동시 반영 |
| 거절 이유 | `REJECTED / COMMAND_ID_CONFLICT` 문구만 확정 | `reason_code`·`reason` 정확한 wire 표현 확정 |
| command payload | 공통 필드와 enum만 확정 | 6개 command별 target·JSON 표 확정 |
| mission 전이 | STOP/CANCEL 의미와 중재 우선순위만 확정 | 허용·거절 전이, 중단 중 대체, 재시작 복구 행동 확정 |
| report 재전송 | 영속 큐·같은 report ID 재전송만 확정 | 재연결 감지, replay 범위·시점, ACK/삭제 여부 확정 |

## 영향과 적용 순서

1. 관제·AMR·System monitor가 위 결정 표에 합의한다.
2. `interfaces.md`, `amr.md`, `control_server.md`와 필요한 `.msg` 상수를 같이 갱신한다.
3. AMR ingress·mission runtime·outbox를 연결하고 관제 송수신을 맞춘다.
4. robot1·robot6 각각 IT-02·IT-12를 수행한다.

혼합 버전에서 check 숫자가 다르면 정상 command를 거절하거나 거절 command를 실행할 수 있으므로 실주행을 금지한다. 재전송은 report ID 중복 제거가 확인된 수신자에서만 활성화한다.
