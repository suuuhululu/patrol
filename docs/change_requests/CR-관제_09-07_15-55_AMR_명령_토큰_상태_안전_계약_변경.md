## 변경 이유

기존 공용 문서에는 UUID v4 command ID, 미정인 명령 확인·재전송, token 재시작 처리, RobotStatus·PatrolReport 필드, heartbeat/E-stop 상세, 배터리·화재 종단 흐름이 남아 있었다. 관제 구현과 AMR 구현이 서로 다른 가정으로 진행되는 것을 막고 로그에서 명령·mission·권한·결과를 사람이 추적할 수 있도록 확정 내용을 공용 계약에 반영한다.

Keepout·안전구역의 상세 설계는 이번 요청에서 확정하지 않는다. AMR 팀이 실제 costmap 구성과 경로 실행 정보를 바탕으로 제시안을 작성하고 관제 담당자가 확인한 뒤 별도 합의한다.

## 변경 전 → 변경 후

| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| command ID | UUID v4 | `cmd-<control_session>-<robot_id>-<command>-<sequence>` |
| mission ID | 상세 미정 | `msn-<control_session>-<robot_id>-<mission_sequence>`, 대피·재개·복귀·도킹에서 기존 mission ID 유지 |

| 중복 보관 | 24시간 또는 1,000개 우선순위 미정 | 24시간 이내 전체와 24시간 경과 항목 중 최신 1,000개 유지 |
| STOP/CANCEL | 차이 미정 | STOP은 재개 상태 보존, CANCEL은 종료 및 CANCELED report |

| 실제 정지 | 확인 방식 미정 | odometry 선속도 ≤0.05 m/s, 각속도 ≤0.1 rad/s, 0.5초 연속, age ≤0.5초 |
| RobotStatus·PatrolReport | 전체 필드 미정 | 공용 문서의 필드와 command·mission·report 관계 적용 |
| heartbeat | 전체 계약 미정 | 5 Hz, timeout 1초, control session·sequence·timestamp |
| LOW | 교대·복귀 상세 미정 | 새 mission 없이 현재 mission의 순찰·복귀·도킹까지 완료; CRITICAL 전환 시 즉시 복귀/도킹 판단 |

| 화재 | 후속 mission·token·부저 순서 미정 | 현재 mission의 순찰·복귀·도킹 완료, 기존 token 종료까지 유지·회수, 이후 다른 로봇 신규 token 금지 |
| 도킹 실패 시 부저 | 도킹 완료 후 OFF 기준 | 다른 활성 화재가 없으면 OFF하고 FIRE_DOCKING_FAILED 관제 경고 |

## 영향과 적용 순서

MissionCommand·CommandCheck·DriveToken·RobotStatus·PatrolReport·heartbeat/E-stop은 관제와 AMR 양쪽이 같은 버전을 적용해야 한다. 혼합 버전에서는 UUID와 구조화 ID, 기존 token 필드와 새 필드가 호환되지 않으므로 실제 주행 시험을 시작하지 않는다.

권장 적용 순서는 공용 메시지 정의 → AMR 수신·발행 → 관제 수신·발행 → 정적 메시지 시험 → 시뮬레이션/정지 상태 시험 → 실제 안전 주행 시험이다. 실패 시 이전 계약을 섞어 실행하지 않고 양쪽을 같은 적용 버전으로 되돌리거나 시험을 중단한다.

화재 발생 후에는 현재 mission의 순찰·복귀·도킹까지 기존 token을 유지하고 종료 시 회수한다. 이후 다른 로봇에 새 token을 발급하지 않는다. token 만료나 E-stop은 화재 흐름보다 우선하며 자동 재발급으로 복구하지 않는다.

## 완료 조건과 검증

- 관련 integration.md 시험 ID: IT-02·03·04·10·11·12·13·14·16
- 추가 시험·기대 결과:
  - 같은 command ID·payload 재전송에서 중복 실행 없이 현재 CommandCheck 또는 기존 report 재전달
  - 같은 command ID·다른 payload는 COMMAND_ID_CONFLICT 거절
  - 각 5초 Check timeout 뒤 동일 ID로 최대 2회 재전송하고 새 ID를 만들지 않음
  - 관제 세션 변경 시 이전 token 폐기, 회수 대상 robot 식별, 실제 정지 전 신규 holder 금지
  - LOW는 현재 mission의 도킹까지 완료하고 CRITICAL 전환 시 즉시 복귀/도킹 흐름으로 변경
  - DOCKED와 CHARGING이 2초 미만이면 도킹 성공·화재 부저 OFF로 판정하지 않음
  - 화재 mission 도킹 종료 후 robot1·robot6 모두 신규 token 미발급
  - 도킹 실패 시 다른 활성 화재가 없으면 부저 OFF 및 FIRE_DOCKING_FAILED 경고
- 실제 실행 결과와 증거: 미실행
- 미실행 또는 BLOCKED 항목: AMR 코드 변경 승인·공용 메시지 구현·양측 배포 전 전체 시험 BLOCKED
